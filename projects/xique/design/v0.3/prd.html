1. 产品命题

为想自由走走、又想了解眼前地点的杭州 City walk 游客，提供与当前地点相符、可追问和随时打断的可信讲解。用户不必反复在地图、攻略与聊天窗口间切换，保留自己的节奏。

待验证命题：“边走边听、想问就问”比地图＋攻略＋普通 AI 问答更省心，且主动讲解不会带来更大打扰。

首轮建议人群：第一次或不熟悉杭州、以中文游览、独行或两人结伴、步行 30～90 分钟、愿意在手机前台使用耳机的成人游客。排除首轮：跟团、驾车导航、室内精确定位、多语言、未成年人独立使用、后台持续通话。排除是验证边界，不是取消原始愿景。

7. 进入正式设计/开发的检查点

  • G0：目标用户、关键问题与替代方案有原始研究记录；决定继续/缩小/转向。
  • G1：PRD、功能优先级、指标、非目标与风险经产品双评审，重要业务取舍由用户确认。技术意见由协调方先归并。
  • G2：先比较视觉参考，展示两种风格方向和关键流程线框；用户挑审美方向后再冻结 UI 方案。只有关键选择提醒用户，不逐个按钮追问。
  • G3：技术方案、任务、测试矩阵与预算准备好后做真实服务开发。前期技术探索保留为探索，不回填成 G0/G1 已通过。

8. 在协作台怎么留痕

需求 → 来源/假设 → PRD版本 → 范围表 → 设计 → 任务 → 代码/评审 → 验收证据。每轮输入固定并绑定摘要，输出隔离。由主执行整理，另两方独立检查“真实痛点/替代方案”及“范围/可测试性/体验”，具体平台和可见型号按实际可用性记录，不把期望型号当调用事实。本版本尚未提交新一轮产品双评审。

现有平台优势待验证：能否发现漏项、减少交接遗漏、追溯改动原因。负担同样计入：协调方装配上下文、UI操作投递、复核时间、冲突与返工。不能以评审字数或模型数量代表价值。

2. 保留原愿景，分开验证与交付

  • 价值验证切片：一条经核实短路线、审定短内容、开始/暂停/结束、来源查看、明确披露的人工辅助问答。可以用静态交互或按键语音研究任务，但不得称为全双工、自动定位或正式交付。
  • 正式工程切片：保留前台真实定位、到点触发、真实流式全双工追问/打断、可信资料及异常恢复。全双工不是自动降为P1；若成本或技术不成立，形成业务取舍卡再由用户决策。
  • 兴趣路线重规划和私密笔记为P1探索，社区/餐饮扩展为P2；出发线框默认看固定候选路线，不暗示已实现推荐引擎。
  • 安全底线不等于“保证实时安全”：真实试走前核对可走性、开放/封闭信息及适用区域/更新时间。必要资料未知或失效时，停止该路线试验并返回官方入口；不靠模型生成安全保证。天气、实时公告接口未接通时明确说明，不能显示合成预警为实时信息。

4. 访谈提纲与数据/现场边界

1. 最近一次在杭州走了哪里、为什么去？让参与者按时间复盘，而非先介绍喜鹊。

2. 哪个时刻想了解眼前地点？当时怎样找、切换几次、是否放弃？没有困扰也原样记录。

3. 有何具体后果：走错、低头、被打断、听不清、资料不信任？分开原话与研究者解释。

4. 是否习惯耳机、是否愿意前台开屏、对位置/麦克风有何顾虑？不把这些当有利样本筛选器。

5. 什么内容值得主动讲、哪些时候绝对不要打扰？希望怎样控制或退出？

6. 讲清静态原型边界后再问兴趣；不先诱导“你是不是需要AI导游”。

研究前分别征得访谈、录音与位置收集同意；不同意录音可用笔记，不强制获取精确轨迹。研究记录去标识，录音/精确轨迹只保存在明确授权的私有位置，不进入公共协作审计；本轮默认不收集、不上传。保存期限和访问者须在招募前说明并得到同意；未约定不得开始收集。

实地执行者先踏勘路线；过街或危险路段不交互；参与者随时退出；恶劣天气、道路封闭、位置异常或任何安全疑虑立即停试。参与者招募、场地与试走需要真实人员参与，当前均未发生。
