    用户手册 / 随用随查

    把想法说清楚，其余一起推进。

    这份手册解释协作台怎么用，以及提交后会发生什么。你负责目标、体验与重要取舍，协调方负责组织执行和核查。

    开发中有新想法，去哪里说？

    你的想法在哪里提出当前会如何处理
    改配色、排版、按钮或文案体验与审美 →保存反馈，协调方评估并安排修改；不自动修改代码。
    补充功能或使用场景定义需求 →保存为新输入，协调方检查与原需求的关系，补充范围和验收条件。
    改核心目标、取消功能或调整优先级页面常驻的“调整方向”保存新方向，并暂停项目后续分发与批准；协调方更新计划后，你再决定何时继续。

    分不清属于哪类时，直接用自己的话描述，不必先判断技术影响。协调方会先整理；涉及方向、明显费用或重要体验取舍，再提出明确选项。

    第一次使用：从哪里开始？
    1. 选择当前项目；新项目先在“定义需求”说想法，必要时填写开发前配置。
    2. 在“项目全貌”查看开发框架，点击阶段卡片进入该阶段的成果、资料和评审。
    3. 在“研发进展”看已登记事实；在“体验与审美”打开真实成果并反馈。
    4. “需要我决定”出现卡片时，比较影响再选择；也可以填写自己的方案。
    怎样提意见，更容易改到点上？

    说明“哪个地方、现在有什么问题、希望改成什么样”，有参考链接可以一起提供。

    例如：“游览中的暂停入口不明显，希望固定在底部；整体保留旅行手册的感觉。”

    想取消或替换当前研发目标，请用“调整方向”，不要只在普通反馈里写“先别做了”。

    提交后，在哪里看处理情况？

    想法和反馈保存在“定义需求”的“我的想法与反馈”，协调方回应后会显示整理结果；研发安排和成果变化在“研发进展”及对应阶段页查看。只有需要你作选择的事项才会形成决策卡。

    目前没有完整自动变更影响卡或逐条需求追踪界面。保存输入不等于已分析影响、调用模型、修改代码或完成验收。

    暂停、调整方向，能立刻停下所有 Agent 吗？

    暂停会拦截本项目后续分发与批准，并尝试停止本机受管任务。外部应用中已经运行的任务，需要协调方另行停止；不能保证点击后瞬间停止所有平台。

    调整方向会保留旧任务、评审与成果。新方向等待协调方更新计划时，不能直接恢复分发。不要把暂停当作撤回已经发生的外部操作。

    怎样理解进度、评审和验收？
    • “已收到成果”表示已回收输出，不代表功能正确。
    • “双评审已收齐”表示意见已到齐，不代表分歧解决或产品通过。
    • “测试通过”只覆盖实际执行的测试，不能代替未测场景。
    • “阶段成果”可以是草案、视觉探索或原型，是否验收需看明确记录。
    哪些能力仍由协调方接力？

    当前的上下文整理、部分跨平台应用投递、影响分析与任务安排仍由协调方处理。页面展示已登记事实，不是所有外部应用的实时心跳。

    不要在需求、反馈或共享资料中粘贴密码、API Key 等凭据。填写链接或路径只是记录引用，不代表系统已读取或授予访问权限。
